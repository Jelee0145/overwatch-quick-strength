## 可复现测量

`node --expose-gc scripts/history-performance-benchmark.mjs` 使用确定性合成账号，与 `ea1b059` 的 slim 投影规则比较。测试中名字、英雄、段位重复较多，gzip 比真实数据更容易压缩；不能用它推断真实账号的压缩率。每次测量不访问私有文件或生产接口。

| 合成账号 | 原 slim JSON | 当前 slim JSON | 当前 gzip | 当前 brotli | 冷计算 | 缓存后不同窗口/统计 P95 |
|---|---:|---:|---:|---:|---:|---:|
| 118 场 | 1,016,513 B | 116,044 B | 5,460 B | 3,271 B | 128.0ms | 3.1ms |
| 500 场 | 1,898,739 B | 296,464 B | 9,645 B | 4,810 B | 355.9ms | 5.6ms |

以上计算 P95 包含摘要生成和 slim 序列化，不含网络、存储验签与浏览器渲染。500 场精简对象缓存约计量 14.7MB；另 20 窗后的 Node GC 堆差约 +128KB，是一次采样，不能据此声称堆内存绝对不增长。完整对象缓存预算不足时不保留，网页专用精简缓存避免因此每次翻窗重新评分。两种模式有独立键，并通过逐字段等价测试核对摘要、预测和可见证据。

## 浏览器验收

可选脚本：`node scripts/history-browser-check.mjs --output <绝对目录>`。需要已有 Playwright 模块与 Chrome，可用 `OWQS_PLAYWRIGHT_MODULE` 指定模块路径、`OWQS_BROWSER_CHANNEL` 指定已有浏览器渠道；不会自动安装浏览器或连接生产环境。当前环境没有 Browser plugin，使用已有 Playwright + Chrome。

流程：本机内存 SQLite 注册并授权合成账号 → 500 场签名历史同步 → 首次图表 → 桌面评分详情 / 手机数据与评分详情 → 手机放大 → 连续翻窗 → 切换统计范围 → 打开历史并完成同步。

首轮 1440×1000 桌面、390×844 手机均完成；每端玩家详情请求 1 次，图表和预测记录可见，评分依据按需恢复，页面非空、无错误覆盖层、pageerror 与 console.error 均为 0。图片资源使用本地构建资产，外部图片请求以空 SVG 替代，地图为未知地图夹具，因此不覆盖真实地图 CDN 可用性。

| 本机 500 场 | 前 20 窗点击→渲染 P95 | 历史面板显示并同步完成 | GC 后堆：初始 / 20 窗 / 40 窗 |
|---|---:|---:|---:|
| 桌面 | 109.9ms | 78.8ms | 3.14 / 3.86 / 3.90 MB |
| 手机 | 92.4ms | 76.3ms | 3.36 / 4.04 / 4.08 MB |

第二个 20 窗堆增量桌面约 37.1KB、手机约 41.6KB，未观察到按窗口数线性累积；这不是无限时长泄漏证明，也不是严格的零增长。每端分析请求 46 次（首窗、相邻预取、40 次翻窗和统计切换），详情请求各 1 次，pageerror / console.error 均为 0。

验证命令结果在本轮 agent-update-log 的完成记录中归档。

以下仍需上线后真实账号验收：真实 118/500 场压缩大小、首屏全部资源 <200KB gzip（当前只验证分析响应）、公网翻窗 P95 <300ms、首次跨设备全量同步时打开历史 <500ms，以及生产 768M MemoryMax 下的长期混合负载。冷计算与首次同步不等于缓存后翻窗耗时。

## 存储迁移与回退

新代码首次读取或写入旧账号时，在同一事务内写入所有原签名批次，再把账号 blob 替换为 v2 元数据并更新容量统计。任一写失败均回滚；迁移不改签名、批次 ID 或 revision。已有 legacy、v2、并发 push、容量拒绝、故障回滚和降级再升级测试覆盖。

**回到本轮之前的代码，不能只 checkout 后启动**。旧代码只认识包含 batches 的账号 blob。应在当前代码还可用时：

1. 停止自动发布定时器和 `owqs.service`，按既有运维流程做 SQLite 在线备份（WAL 场景使用 SQLite backup API，不能仅复制主文件）。
2. 在 `/opt/owqs-work` 执行 `node scripts/history-storage-rollback.mjs --database /var/lib/owqs/state.sqlite3`，先 dry-run。工具只输出账号数量，不输出账号、签名或配置。
3. 执行相同命令加 `--apply`。它逐批核对 SHA-256，事务恢复旧格式及目录字节统计，随后清理对应独立批次；任一批次缺失或哈希不符则事务失败。
4. 确认工具成功后 `git checkout deploy/<日期-时分>`，重跑 `node scripts/deploy-local.mjs`，验证 revision、服务与网页，再恢复定时器。服务停止期间禁止并发写数据库。

dry-run/恢复/再升级等价性与故障中断已在合成数据测试；本轮没有操作生产数据库，也没有执行生产回退。
