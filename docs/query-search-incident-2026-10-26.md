## 本地修复

`src/services/matches.mjs` 在现有有限次大小写查找全部无结果后，通过同一操作调度器安排一次 `/queryCard` 本人资料回退。

- 只接受上游返回的完整 BattleTag 与请求完整 ID 一致（含数字编号，允许大小写恢复）且有 customerToken 的结果。
- 本人资料属于其他账号、缺少完整名字或 token 时拒绝替代，不猜昵称或编号。
- 回退是查询 account 阶段的一部分，使用 high 优先级、现有请求计数、检查点、截止时间、取消与限流恢复机制，不额外建任务或计费。
- 有已保存历史仍无法取得资料时，返回可重试的上游错误与“历史仍可查看”提示，不把它判定为用户输入了不存在的玩家。
- 未知 ID 且本人资料不匹配时仍按原有未找到处理；没有数据库或签名格式变更。

**范围限制：本人回退本身只覆盖查询凭证实际绑定的账号；后续新增的共同对局回退另见收尾记录，也不能解决任意其他玩家的搜索。** 原始搜索接口仍可能为空；`refresh-dashen-credentials.mjs` 是直接接口诊断，未自动使用业务查询回退，直接搜索仍空并不否定该回退有效。

## 不依赖昵称搜索的可用路径（已实测）

官方搜索空响应期间，下列链路仍完整可用（生产机真实凭证，5 次请求，1 req/s）：

| 步骤 | 结果 |
| --- | --- |
| `/queryCard`（凭证参数） | 返回本人资料与 `customerToken` |
| `/customer/queryMatchList`（本人 token） | 12 场近期对局 |
| `/customer/queryMatchInfo`（本人 token） | 该场 10 名参与者，10 个他人 `customerToken` |
| `/customer/queryCard`（他人 token） | 返回该玩家资料，含其 `customerToken` |
| `/customer/queryMatchList`（他人 token） | 返回该玩家 12 场对局 |

因此：**从已知玩家出发可以扩散到同场其他玩家**，无需昵称搜索。已验证脚本：

- `scripts/diagnostics/dashen-token-probe.mjs`：验证凭证 → customerToken → 列表／详情链路。
- `scripts/diagnostics/dashen-player-probe.mjs`：验证他人 customerToken 能否取到其资料与对局。
- `scripts/diagnostics/upstream-credential-check.mjs`：判断凭证是否失效（本事件中输出 `empty-success-everywhere`）。

**边界**：扩散路径只能触达“已出现在可读取对局中的玩家”。陌生昵称若从未出现在这些对局里，仍无 token 可用，因此任意昵称查询在搜索恢复前不可用。该路径还依赖详情接口持续返回他人 token，属上游实现细节，可能随时收紧；沿用它会显著增加请求量，与当前 8 req/s 全局预算冲突，需单独评估。
