# 快速强度图生成工具

双击 `启动工具.cmd` 打开本地网页。需要 Python 3.10 或更新版本，无需第三方依赖。网页使用白色为主的橙灰配色，直接提供在线查询。

## 查询与导出

1. 填写完整战网昵称，例如 `TWISTZZ#5992`。
2. 凭据设置默认收起。首次使用时展开“大神查询凭据”，填入 Role ID 和 Token，然后加密保存。已保存凭据直接使用，不将 Token 回填网页。
3. 选择场数，点击“查询并生成”。竞技段位按唯一玩家查询、顺序限速，支持进度与停止。英雄与战斗数据直接取已返回的对局详情，不逐人追加英雄时长查询。
4. 点击图表地图列或切换“逐场玩家明细”，查看对局英雄、击杀 / 助攻 / 死亡、伤害、治疗、抵挡和参考段位。
5. 导出 PNG、SVG 或包含计算来源和游戏数据的 JSON。PNG 为图表两倍分辨率。

网页自动恢复最近一次完成的本机查询，不提供 JSON 导入功能。开发研究快照仅用于源工作区或单独的 development-fixtures 预览，不作为默认生产数据，不随发布包提供。

## 图表阅读 v3.1

顶部并列显示综合强度（包含估算）与实测场次均值，两者字号一致，并注明估算场数、实测场数和可查玩家覆盖率。实测和估算使用同款圆点、范围框与折线，青色表示实测，橙色表示估算；场次标签与图例明确标注来源。触及估算点的连线用橙色，直线连接，不平滑制造走势。青色框表示本局职责段位范围，灰色细线表示全职责范围，橙色斜纹框表示估算参考范围。

每场直接标注均值、胜负、地图、时间和可查人数。实测均值只代表可查玩家样本；直方图只统计已知段位，不加入估算。点选地图列或用 Tab、Enter / 空格切换场次，可查看“段位参考 + 战斗辅助 ≈ 本场估算”及辅助权重、参考来源。点击“放大阅读”后可横向滚动，小屏也可左右滑动图表。

新版采用暗灰战术面板、低亮度地图、青橙双色和细线装饰，保持网页白色橙灰配色。强度估算 v2.5、定位评级 v2.0、图表 v3.2。原始竞技段位、战斗数据与英雄评分保留；稀疏样本场次另显示融合估值。PNG / SVG 导出保留相同图例和样本说明，JSON 记录版本与来源。

## 英雄与战斗数据

英雄直接来自对局接口的 `heroGuid`，不表示已核验的最长使用英雄。战斗数据是本局累计值，缺失项显示 `—`，真实的 0 保留显示。

新查询从原有对局详情请求中保存这些数据，不增加请求。旧快照若未保存游戏数据，选择场次时仅补取该场详情，保留已有段位快照；补取结果写入本机最近查询，刷新后无需再取。读取失败会显示明确状态，并提供本场重试按钮。参考接口结构：[Overstats queryMatchInfo](https://github.com/AddOneSecondL/Overstats/blob/main/src/client/api_structure/queryMatchInfo.md)。

## 算法

参考 [Overstats 快速强度引擎](https://github.com/AddOneSecondL/Overstats/blob/main/src/modules/dashen_quick_strength/engine.py)。算法版本 2.4：有段位场次仍取可用玩家段位的均值，整体对各场等权平均；图中同时显示按玩家位平均。新版本仅优化缺失场次的估算。

- **职责优先，跨职责补充**：先匹配本局英雄职责，缺少时取接口第一条记录。延续此前计算行为，仅改名称。
- **仅匹配本局职责**：只使用本局职责，遵循严格职责口径。
- **最高已知职责段位**：取玩家所有有效职责段位的最高值。

指定回退赛季功能已移除，新查询仅取当前赛季。已有快照中的回退与跨职责参考保留原始来源，并标明采集时间。段位优先使用接口的 rankName 与有效 rankSubTier（1～5）。旧快照缺少小段时，兼容原压缩编码以及明确标为 Emerald / 翡翠的 445～449 编码；445 为翡翠5、446 为翡翠4、447 为翡翠3、448 为翡翠2、449 为翡翠1。没有翡翠名称时不擅自套用这个编码。强度对应青铜 500、白银 1000、黄金 1500、白金 2000、翡翠 2500、钻石 3000、大师 3500、宗师 4000、英杰 4500；每个小段相隔 100，未知格式不猜测。

默认对无段位和段位稀疏的场次计算融合估值：按独立玩家去重，跨职责与回退赛季降权，结合其他玩家近期对局和定位战斗表现。战斗修正相对参考基数限制 ±35%，不再固定 ±350 点。双方悬殊既降低正向辅助，也额外向下修正。完全无段位锚点时使用随表现变化的动态规则参考，不显示推定段位徽章。橙色上下界按本场证据逐场计算，不是统计置信区间。个人段位、覆盖率、直方图和原始可查均值保持原始口径。详见《强度估算规则.md》。

## 后台与凭据

双击 `后台启动.cmd` 启动隐藏的独立本机进程。关闭网页不影响服务与查询；重新打开 http://127.0.0.1:18765 自动恢复已完成结果，或接回进行中的查询。双击 `停止后台.cmd` 停止。工具不安装 Windows 服务，不修改开机启动；关机后需再次启动。普通启动入口在默认端口被占用时可选取空闲端口，停止入口仅对应默认端口。

凭据使用 Windows 当前账户 DPAPI 加密保存于 `.private/credentials.dpapi`。取得 Token 后，查询不需要挂着浏览器；Token 过期后需重新获取。检测成功只代表最近鉴权可用，不保证永久有效。查询结果、网页返回、导出与 ZIP 不包含鉴权 Token 或 customerToken；ZIP 排除 `.private/`，本地服务限制私有文件与非本机来源访问。

## 素材与验证

官方九个段位徽章已内嵌，按平均强度选择大段位，文字保留小段。地图背景按本地官方配置补齐并内嵌导出；下载时禁用 PNG/SVG 导出，失败可重新生成重试。英雄小头像直接从官方素材地址加载，网络不可用时保留英雄名称。

TWISTZZ 的此前 10 场真实记录已补齐 113 个玩家位的战斗数据。v2.1 修复翡翠编码遗漏后，新增可识别样本会影响图表均值、覆盖率和估算场次；每场均值再按场次等权汇总的规则不变。真实接口已核验 446 / Emerald / 4 为翡翠4（2600），447 / Emerald / 3 为翡翠3（2700）。Node 算法检查及 Python 采集、数据字段白名单、0/缺失值、加密与本地访问检查通过；浏览器核对了真实场次的英雄和战斗数据。英雄时长不逐人核验。

## v2.1 段位兼容验证

前后端使用同一组 26 个格式案例，覆盖名称与小段优先、旧编码、新翡翠编码、错误小段、未知名称和非法值。当前赛季、回退赛季、三种职责策略、玩家明细、职责区间、全职责区间、直方图和覆盖率统一使用新的解析结果；后端也按此判断是否需要回退查询。原始 rankScore 保留，新增保存 rankSubTier，不改写原始采集记录。

## 定位表现评级 v2.0

玩家明细最右列显示 S / A / B / C / D，英雄名下显示定位分类；表格新增最后一击、单独消灭，未返回显示 —。点击评级可查看定位模板、默认打法、英雄特调、各维度预算和每项参考来源。网页、文档统一称“抵挡”，底层接口仍使用 resistDamage。

规则集中在 `rating-rules.js`，包括 9 个定位模板、54 位英雄映射、Poke / 放狗 / 地推抱团词条及英雄特调。模板基准按公开快照取定位中位数；最后一击和单独消灭参考线采用明确标注的规则比例，不冒充实测均值。生存与 K/D 固定 40%，重叠击杀计数共用收尾预算；单独消灭缺失完全不算，缺失维度不增加生存权重。

禅雅塔、无漾使用兼顾治疗与输出的模板；天使、自愈坦、狙击及部分功能输出保留特调。短局只按每 10 分钟归一化，不额外扣分。等级属于整局规则估评，不能量化实际英雄参战时间和关键技能；详见 `英雄表现评级说明.md`。

新评分接入强度估算 v2.5，原始个人段位保持原样，样本稀疏场次另行融合。后续维护基准可手动运行 `python refresh_benchmarks.py`；正常显示英雄和游戏数据无需额外英雄时长请求。


## v2.5 近期参考与范围更新

查询会自动使用已有近期参考；有新增对局或没有参考数据时，在现有采样预算内补充。抽样上限12人、每人2场、额外64次请求；没有新增对局且已有参考时直接复用，不提供单独补充或本地生成入口。

段位样本少于 4 名或当前同职责覆盖不足 60% 时，可启用融合估值。战斗修正相对参考基数限制 ±35%；缺少全部段位锚点时使用动态表现规则参考，取消固定 2500。橙色范围按每场局部样本、近期证据、离散程度和双方均衡重新计算，样本充分一致时收窄，依据不足时放宽；不是统计置信区间。详见《强度估算规则.md》。


## 个人段位预测 v1.0 / 图表 v3.3

顶部第一项为“强度预估”，表示对局环境；第二项为“个人段位预测”，结合本人每十分钟定位表现与排除本人的段位环境，按职责分别预测，默认有效游玩最多的职责。点击“个人段位预测依据 · 分职责”可查看原始实测均值、各职责预测、实际已查段位、样本门槛、每场环境基准和修正。样本不足不强行给出段位。

“对局模式”可选择全部快速模式、快速 5v5 或快速 6v6。大神快速列表同时包含两种人数；选中某一模式后，查询只采集该人数对局，图表和统计也只使用该模式。替补按模式人数上限判断：5v5 超过 5 人、6v6 超过 6 人才视为含替补。旧缓存里没有记录模式的对局无法确认人数，只在“全部快速模式”下参与分析，重新查询后会自动补回模式。

预测仅为规则参考，最大表现修正±35%，最高中可信，未校准为真实竞技定级或MMR。回退、跨职责及历史推导参考降权；个人实际段位和直方图保持原始数据。详见《个人段位预测规则.md》。当前离线预览已检查，浏览器工具受URL安全策略阻止，浏览器实机交互检查仍待确认。


## 自动增量查询与界面简化

现在只保留“查询最新对局”作为获取数据入口。图表标题、场数、玩家范围、段位口径及背景设置变化后自动重绘，不重新查询玩家；标题输入使用150ms延迟合并更新。指定赛季和正常地图加载状态提示已移除。

查询按战网账号、区服和Dts参数隔离缓存，先读取最新列表，再按对局ID去重合并，选最近N场。详情齐全的缓存直接复用，新增或不完整记录才读取详情。例如新5场+已有5场只读取5场详情。每个分区最多保留50场；改变账号、区服或Dts不会混用。当前窗口外的旧场次仍可保留在该分区以便以后查询20场时复用。

竞技段位和对局详情分别记录采集时间。新读取的对局玩家可以复用6小时内成功取得的段位快照；超过期限则查询其当前段位，并同步到复用场次中的同一玩家。旧场次没有新出现玩家的段位保持旧快照与日期，不假装是本次重新查询。上游没有新列表时明确标注本次展示已有缓存；失败和停止时保留之前结果。

开发预览位于输出目录 development-fixtures，与产品目录分开。它使用脱敏的固定真实快照、禁用查询，不提供上线的导入功能；测试模拟的新对局不会写入生产数据。详见《自动增量查询说明.md》。

## 预估可信度显示

顶部第三项改为预估可信度百分比；场次及个人预测不再显示低/中可信标签。百分比是对局证据评分，不是命中概率。原始可查玩家位在展开依据与 JSON 中保留。详见《预估可信度规则.md》。
